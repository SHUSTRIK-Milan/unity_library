### Теория

Определения:
> *Ассет* (Asset) – любой файл или элемент данных, например *Игровой объект* (GameObject) или *Меш* (Mesh)
> *Игровой объект* (GameObject) – объект находящийся на сцене
> *Меш* (Mesh) – модель (к примеру та, что вы экспортируете из Blender'а)
> *Префаб* (Prefab) – шаблон для ассета

#### Введение

Довольно удобно работать с GameObject в сцене, добавляя компоненты и изменяя их значения на нужные вам в инспекторе. Однако, это может создать ряд проблем в таких случаях, когда вы работаете над созданием NPC, объектом или предметом, который многократно встречается в сцене. Вы, конечно, можете просто скопировать эти объекты для создания дубликатов, но все они будут редактироваться независимо друг от друга. Обычно вы желаете, чтобы все экземпляры отдельно взятого объекта имели одинаковые значения свойств, чтобы при редактировании одного такого объекта в сцене вам не пришлось повторно вносить те же изменения и во все остальные копии.

К счастью, в Unity можно создавать префабы. Это особый тип ассетов, позволяющий хранить весь GameObject со всеми компонентами и значениями свойств. Префаб выступает в роли шаблона для создания экземпляров хранимого объекта в сцене. Любые изменения в префабе немедленно отражаются и на всех его экземплярах, при этом вы можете _переопределять_ компоненты и настройки для каждого экземпляра в отдельности.

**Важно:** Когда вы перетаскиваете файловый ассет (например, меш) в сцену, будет создан новый экземпляр такого объекта и все такие экземпляры изменятся при изменении оригинального ассета. Однако, хоть его поведение и похоже, но ассет - это _не_ префаб, так что у вас не выйдет добавить к нему компоненты или использовать любые другие описанные ниже свойства префабов.

#### Использование префабов

Вы можете создать префаб, выбрав Asset > Create Prefab и перетащив объект со сцены в “пустой” префаб, появившийся в проекте. После чего можно создавать экземпляры префаба просто перетаскивая его из окна Project на сцену. Имена объектов-экземпляров префабы, будут подсвечиваться синим в окне Hierarchy (имена обычных объектов имеют чёрный цвет).

![[../00_Ресурсы/Pasted image 20261020095500.png]]

Как уже упоминалось выше, изменения в префабе автоматически применятся ко всем её экземплярам, однако вы можете изменять и отдельные экземпляры. Это полезно например в случае, когда вы желаете создать несколько похожих NPC, но с внешними различиями, чтобы добавить реалистичности. Чтобы было чётко видно, что свойство в экземпляре префаба изменено, оно показывается в инспекторе жирным шрифтом (если к экземпляру префаба добавлен совершенно новый компонент, то _все_ его свойства будут написаны жирным шрифтом).

![[../00_Ресурсы/Pasted image 20261020095328.png]]

Например здесь у экземпляра префаба изменены значения "Is Trigger" и "Provides Contacts", что можно заметить по жирному начертанию и синему прямоугольнику слева

#### Редактирование префаба из его экземпляров

Инспектор экземпляра префаба содержит три кнопки, которые у обычных объектов отсутствуют: _Select_ (Выделить), _Revert_ (Отменить) и _Apply_ (Применить).

Кнопка _Select_ выделяет файл префаба, из которого был получен данный экземпляр. Это позволяет быстро найти и отредактировать оригинальный префаб, применяя изменения ко всем его экземплярам. Однако, вы также можете сохранить переопределённые свойства из экземпляра в сам оригинальный префаб с помощью кнопки _Apply_ (изменённые значения положения и вращения трансформации не применяются по очевидным причинам). Это позволяет эффективно редактировать все экземпляры через любой из них, и это быстрый и правильный способ вносить глобальные изменения. Если вы экспериментируете с переопределением свойств, но в итоге решаете, что изначальные свойства (заданные в префабе) для вас предпочтительнее, то вы можете отменить все сделанные переопределения с помощью кнопки _Revert_, вернув экземпляр в изначальное состояние.

![Картинка](./00_Ресурсы/1 ЛР/Pasted image 20261020095620.png)

Чтобы редактировать именно префаб, вам следует дважды нажать по нему в окне Project, то есть в списке файлов.

### Практика

Давайте приступим к практической части и попробуем создать свои префабы.
1. Для начала создадим на сцене любой объект, к примеру простой 3D куб.
2. Для соблюдение негласных стандартов Unity создадим в окне Project (списке файлов) папку под названием Prefabs. Это делается, как минимум, для вашего удобства, чтобы не захламлять рабочее пространство.
3. Перетащите куб со сцены в открытую папку Prefabs ![[../00_Ресурсы/Unity_WChzsYE5Uh.gif]]
4. Отлично. Вы создали префаб.

Теперь давайте создадим несколько экземпляров этого префаба. Для этого у нас есть два способа:
1. Перетащите префаб из папки Prefabs на сцену. Таким образом вы создадите его экземпляр![[../00_Ресурсы/Unity_3iMQKM1qLF.gif]]
2. Если у вас уже есть объект на сцене (любой, даже пустой) вы можете заменить его префабом. Для этого: нажмите по нему правой кнопкой мыши -> Prefab -> Replace![[../00_Ресурсы/Unity_K48PXoRvgf.gif]]

Теперь у нас есть несколько экземпляров одного префаба на сцене. Давайте изменим сам префаб:
1. Самостоятельно создайте новый материал любого цвета и перейдя в [[#^prefab-editor|Настройки префаба]] назначьте ему новосозданный материал.
   > *Напоминание*: чтобы перейти в настройки префаба – дважды кликните по нему в окне Project (там где файлы хранятся, папка Prefabs)
2. Должно получиться следующее:
   ![[../00_Ресурсы/Pasted image 20261020102309.png]]
3. Теперь посмотрим как это выглядит на сцене:
   ![[../00_Ресурсы/Pasted image 20261020102354.png]]

Все наши кубы перекрасились в тот же цвет, что и их шаблон, то есть префаб. Значит экземпляры префаба наследует все изменения.

Аналогична ситуация и с компонентами. Все компоненты, которые есть у префаба - перенесутся и на его экземпляры. Таким образом, если у префаба будет Rigidbody, то все его дочерние объекты будут также обладать физическими свойствами.

Попробуем поменять конкретный экземпляр вне зависимости от родительского объекта:\
1. Создадим новый материал уже с другим цветом
2. Не заходя в настройки префаба, назначим одному из дочерних объектов новый материал
3. Посмотрим что вышло:
   ![[../00_Ресурсы/Pasted image 20261020102642.png]]
4. Помимо того, что изменение применилось только на один объект, внутри его инспектора поле Materials выделяется как измененное, то есть отличающееся от префаба:
   ![[../00_Ресурсы/Pasted image 20261020102728.png]]
5. А что если мы хотим применить эти изменения? Для этого перейдем в ранее описанную вкладку Overrides и нажмем клавишу Aplly All (применить у всех):
   ![[../00_Ресурсы/Pasted image 20261020102918.png]]
После всего этого – все наши кубы окрасились в зеленый цвет. Поскольку мы применили изменение Cube(1), а конкретно его компонента Mesh Renderer на весь префаб, а остальные дочерние объекты подхватили это изменение по цепочке.

Префабы отлично подходят под ситуацию когда мы можем обобщить объект к чему то одному.

Например: игра воллейбол
Два игрока, мяч, сетка. Игроки схожи между собой как две капли воды за исключением одного - у них должно быть разное управление. Неопытный разработчик станет делать копию скрипта 1ого игрока, заменит там буквы управления и добавит эту копию на 2ого игрока. Казалось бы, что здесь плохого?

А что если вам захочется как-либо изменить функционал игроков? Вы поменяете скрипт 1ого игрока, а со вторым как быть? Копировать новый функционал и прокидывать его в другого? И долго так будет продолжаться? А что если игроков не 2, а 20? Копировать придется в 20 игроков?

Вы уже могли догадаться, что здесь отлично подойдет префаб - префаб игрока. Создаем одного игрока, объявляем его как префаб и пишем для него универсальный скрипт. Универсальный скрипт? Что это такое?

1. По аналогии с папкой Prefabs, рядом создайте папку Scripts
2. Создадим там новый скрипт, вы можете дать ему любое название, я назвал ResizableObject
3. Напишем следующий код:
```c#
public class ResizableObject : MonoBehaviour
{
    // Переменная отвечающая за размер
    // Значение по умолчанию: 1
    public float scale = 1f;

    void Update()
    {
        // Каждый кадр меняем размер на переменную scale
        // Vector3.one = new Vector(1,1,1)
        // При умножении единичного вектора на любое число
        // все его значения (x,y,z) умножаются на это число
        // Vector3.one * 5 = new Vector(5,5,5)
        transform.localScale = Vector3.one * scale;
    }
}
```
4. Теперь добавим наш скрипт внутрь префаба (именно префаба, так чтобы все экземпляры подхватили его)
5. На выходе получаем следующую возможность: 
   ![[../00_Ресурсы/Unity_6kcDzZ9JyV.gif]]
Универсальность скрипта заключается в том, что мы не задаем строгое значение размера или клавиш управления. Мы оставляем эти поля изменяемыми, чтобы мы могли менять их под каждый из экземпляров, при том, что вся остальная логика остается прежней для всех.

**Самостоятельно выполните описанную выше работу**

Помимо того, что префабы удобно использовать как общий шаблон, их удобно использовать как те объекты, которые должны создаваться в момент игры. Например: монетки, пули, NPC и прочее. Попробуем поработать и с этим.

1. Создадим пустой объект (ПКМ в иерархии - Create Empty)
2. Добавим новый скрипт CubeSpawner и назначим его на этот пустой объект
3. Напишем следующий код:
```c#
public class CubeSpawner : MonoBehaviour
{
    // Префаб, который мы будем спавнить
    public GameObject prefab;
    // Таймер для создания объектов порционно
    float timer_start = 5f;
    float timer;

    private void Start()
    {
        timer = timer_start;
    }

    void Update()
    {
        // Отнимаем из таймера время между кадрами
        timer -= Time.deltaTime;

        // Если прошло 5 сек.
        if(timer < 0)
        {
            // Instantiate - создает объект
            // 1 аргумент - объект, который создаем
            // 2 аргумент - позиция
            // 3 аргумент - поворот (Quaternion.identity - это нулевой поворот)
            Instantiate(prefab, transform.position, Quaternion.identity);
            
            // Возвращаем таймер
	        timer = timer_start;
        }
    }
}
```
4. В инспекторе укажем Prefab - наш префаб (для этого перенесите туда объект)
